The Starting Point
2 / 11
The question that matters

The question is never:
"Can I build this?"
It's: "Do I understand this?"

When you find an AI product you love, you're really seeing a logic: data comes in, AI processes it, value comes out. That logic is replicable — in any domain, with the right tools.

The Framework
3 / 11
Five moves

Every AI product can be reverse-engineered with this sequence.

01
See It
Find a product you'd pay for. Ask: who uses it, how often, and why does it work?
02
Deconstruct
Answer three core questions about its input, what the AI does, and what the user receives.
03
Map the Stack
Identify the tool category for each function. You're choosing tools, not writing code.
04
Differentiate
Find your vertical. The gap between "general" and "yours" is where the value lives.
05
Ship
Direct AI to implement. Test in layers. Iterate with real users. A working v1 beats a perfect plan.
Step 02 · Deconstruct

The three questions

You don't need to read the code.
You need to answer these.

1
What is the input?
Where does raw data come from? APIs, RSS feeds, user uploads, databases — everything starts here.
Data source
2
What does the AI actually do?
Filter? Summarize? Generate? Classify? Most AI products do one or two things well — not everything.
AI function
3
What is the output?
What does the end user receive and experience? Email? Dashboard? Report? Conversation?
User value

Where AI Fits
8 / 11
The division of labour

This is not about AI doing everything.
It's about knowing which part is yours.

You bring
  • Domain expertise and professional context
  • The product logic — input, AI function, output
  • Judgment on what "good" looks like
  • The choice of vertical and audience
Claude Code brings
  • Implementation — writing, debugging, connecting tools
  • Navigating libraries and APIs at speed
  • Handling errors and edge cases
  • Turning your logic into working code
The more precisely you can describe what you want, the better AI can build it. Clarity is the skill.

The actual blockers
→
Vague problem definition
Vague input → vague output. Be precise about what you want.
→
Too broad a niche
"Business news" is a category. "Cocoa supply chain risk" is a product.
→
Low tolerance for iteration
Every build breaks. Reading errors as feedback is the skill.
